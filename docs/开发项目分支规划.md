## 📋 分支策略概述

本项目采用 **Git Flow 分支模型**，支持模块化开发、并行协作和稳定发布流程。

## 📌 主要分支说明

### 1. **main** - 主分支

**用途**: 生产环境代码，只接受通过测试的稳定代码

**规范**:
- 从 release 或 hotfix 分支合并
- 包含完整的测试验证
- 标记版本号

**示例**: `v1.0.0`, `v1.0.1`

---

### 2. **develop** - 开发分支

**用途**: 当前开发成果的集成分支，所有功能开发从这里开始

**规范**:
- 从 main 分出
- 所有新功能从这里创建特性分支
- 定期合并功能分支到 develop
- 合并到 main 前需通过完整测试

---

## 🐛 修复分支说明

### 8. **bugfix/** - Bug修复分支

**用途**: 修复生产环境或开发环境的bug

**规范**:
- 从 main 或 develop 创建
- 快速修复，立即合并回主分支
- 提交信息包含 `fix:` 前缀

**示例**: `bugfix/fix-login-error`

---

### 9. **hotfix/** - 紧急修复分支

**用途**: 紧急生产环境问题修复

**规范**:
- 从 main 创建
- 修复后立即合并到 main 和 develop
- 提交信息包含 `hotfix:` 前缀
- 标记版本号

**示例**: `hotfix/fix-payment-callback`

---

## 📦 发布分支说明

### 10. **release/** - 版本发布分支

**用途**: 版本发布前的测试和验证

**规范**:
- 从 develop 创建
- 进行完整的回归测试
- 收集用户反馈
- 合并到 main 和 develop

**示例**: `release/v1.0.0`

## 🚀 工作流程

### 新功能开发流程

1. **开始开发**
   ```bash
   git checkout develop
   git checkout -b feature/backend-new-feature
   ```

2. **开发工作**
   - 进行代码开发
   - 编写测试用例
   - 更新文档

3. **提交代码**
   ```bash
   git add .
   git commit -m "feat(backend): 新增XXX功能"
   ```

4. **推送分支**
   ```bash
   git push -u origin feature/backend-new-feature
   ```

5. **创建Pull Request**
   - 在代码审查后合并到 develop

6. **完成功能**
   ```bash
   git checkout develop
   git merge feature/backend-new-feature
   git push
   ```

---

### 版本发布流程

1. **创建发布分支**
   ```bash
   git checkout develop
   git checkout -b release/v1.0.0
   ```

2. **版本标记**
   ```bash
   git tag -a v1.0.0 -m "Version 1.0.0 Release"
   ```

3. **合并到 main**
   ```bash
   git checkout main
   git merge release/v1.0.0
   git push origin main
   ```

4. **合并回 develop**
   ```bash
   git checkout develop
   git merge release/v1.0.0
   git push origin develop
   ```

---

### 紧急修复流程

1. **创建 hotfix 分支**
   ```bash
   git checkout main
   git checkout -b hotfix/fix-critical-bug
   ```

2. **修复问题**
   - 快速修复bug

3. **提交修复**
   ```bash
   git add .
   git commit -m "hotfix: 修复XXX紧急问题"
   ```

4. **合并到 main 和 develop**
   ```bash
   # 合并到 main
   git checkout main
   git merge hotfix/fix-critical-bug
   git push origin main

   # 合并到 develop
   git checkout develop
   git merge hotfix/fix-critical-bug
   git push origin develop
   ```

## 🎯 分支使用建议

### ✅ 推荐做法

1. **长期维护分支**
   - `main`: 只合并稳定代码
   - `develop`: 作为开发主线

2. **功能分支**
   - 每个功能一个分支
   - 分支生命周期短（1-2周）
   - 完成后及时合并

3. **测试分支**
   - `release` 分支进行完整测试
   - `hotfix` 分支快速修复

4. **代码审查**
   - 所有功能分支都需代码审查
   - 使用Pull Request流程

### ❌ 避免做法

1. **不要直接在 main 开发**
   - 保证生产环境稳定性

2. **避免分支长时间未合并**
   - 避免分支臃肿

3. **不要在 develop 上直接提交**
   - 使用功能分支

4. **避免忘记合并**
   - 定期清理已合并分支
